Colour accessibility

Every colour pair the system actually renders was measured against WCAG 2.2. Text pairs are held to 4.5:1 (AA) and non-text UI boundaries to 3:1 (1.4.11). Nothing in the tables below is aspirational — these are computed ratios for the shipping token values.

Deliberate exemptions

TokenRatioWhy it is exempt
--text-disabled2.6:1WCAG 1.4.3 exempts inactive controls. Disabled state is never the only signal — the control also loses its fill and takes cursor: not-allowed.
--border-subtle1.3:1Decorative only: card edges and dividers. No control is identified by it, so 1.4.11 does not apply. Anything that does bound a control uses --border-control instead.
--border-default1.3:1Same — table rules and card separators. Form fields never use it.

Beyond contrast

Colour is never the only signal
Every status pairs a colour with a glyph and a word: Alert carries ✓ / i / ! / ×, Badge carries its label, field errors carry text. A red-green colour-blind user loses nothing.
Focus is always visible
One ring token on every focusable element at 6.9:1, including destructive buttons. No component removes the outline without replacing it.
Hit targets
Controls are 38px minimum with the label inside the target, clearing the 24px of WCAG 2.5.8. Mobile layouts raise this to 44px.
Not yet verified
Screen-reader labelling and keyboard traps need testing in a real build — static contrast maths cannot cover them. Dark theme tokens do not exist yet and will need their own audit.
