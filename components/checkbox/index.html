Checkbox

Carried over from the previous structure
This page carries its content from the previous structure, moved across unchanged. It hasn't been rewritten to the new format yet.

Examples

Multiple selection. The description line is optional.

Guidance

The following comes from the shared choice controls guide, which covers this component alongside its siblings.

Choosing a control

ControlChoicesAppliesUse for
CheckboxZero to manyOn saveIndependent options in a form with a submit button. Notification types, filters, consent.
RadioExactly oneOn save2–5 mutually exclusive options that should all stay visible.
SwitchOn or offImmediatelyA setting that takes effect the moment it moves. No save button anywhere near it.
SelectOneOn saveMore than five options — see Selection inputs.
TagZero to manyImmediatelyFilters that re-query as you tick them. A checkbox that applies instantly is really a chip.
Do

A setting that applies instantly is a Switch. The user flips it and the shop is paused.

Don't

A checkbox plus Save for a single instant setting. Two interactions for a change that needed one.

Anatomy

1
Control
20px for checkbox and radio, 44×26px for the switch. Fixed size at every text size.
2
Label
14px, part of the click target. A label the user cannot click is a 20px target instead of a 200px one.
3
Description
Optional 12px line in --text-tertiary. Explains consequence, never restates the label.
4
Gap
12px between control and label; 16px between rows in a group.
5
Alignment
Control aligns to the first line of the label, not to the block centre — otherwise a two-line label floats the box.

Checkbox

Independent choices. Ticking one must never change another — if it does, these are radios or a select.

SingleA lone checkbox is legitimate for consent — "I agree to the terms". Never for a setting that applies immediately.
DefaultPre-tick only what the user would choose anyway. Pre-ticked marketing consent is a dark pattern and unlawful in most of Europe.
Never invert"Don't send me email" makes ticking mean off. Phrase the label positively so checked always means yes.
Checkbox · label, description, checked, disabled, onChange

Indeterminate

A parent whose children are partly selected. It is a display state only — the user can never set it, they can only clear or complete the group.

ClickingAn indeterminate parent selects all on first click, then clears all on the second. It never returns to indeterminate by itself.
ScopeIn a table header it selects the current page only, and says so. "Select all 486" is a separate explicit action.

Radio

One of a few, all visible. The moment a set grows past five, the visibility that justifies radios stops paying for the vertical space.

Always defaultOne option is preselected — the safest or most common. An empty radio group makes the user choose before they understand the choice.
No deselectRadios cannot be unset by clicking. If "none" is valid, it needs its own option.
DescriptionsRadios carry the most consequential choices in a form. Use the description line — price, duration, effect — so the choice is informed.
Radio · name, value, label, description, checked, onChange

Switch

Applies immediately. No save button, no confirmation, no "apply changes" — if any of those exist on the screen, this should have been a checkbox.

Vacation modeBuyers see your shop as paused
Auto-relistUnsold listings renew every 30 days
PositionIn a settings list the switch sits right-aligned, opposite its label. In a form row it sits left, like a checkbox. Pick one per surface.
LabelNames the feature, not the state: "Vacation mode", never "Vacation mode: on". The switch already shows the state.
No groupSwitches are independent. Three switches where only one may be on is a radio group.
Switch · label, checked, disabled, onChange

States

UncheckedHoverCheckedFocusDisabled Checkbox ✓✓ Radio Switch
HoverDarkens the border, not the fill. A 20px box is too small for a fill change to read as anything but an error.
DisabledAlmost always needs a reason next to it. A dead checkbox with no explanation is a dead end.

Groups & layout

Do

One column. The eye scans a single edge and the group reads as a set.

Don't

Horizontal rows: labels of different widths break the rhythm, and it is unclear which label belongs to which box.

Group labelEvery group needs a heading, marked up as a legend. "Notify me about" turns three orphan checkboxes into one question.
Spacing16px between rows, 32px between groups. Rows closer than 16px make the 44px targets overlap visually.
OrderMost common first, or a natural order — cheapest to fastest. Never alphabetical for options with an inherent sequence.
Long listsPast about eight checkboxes, add a search field or move to a MultiSelect.

Validation

Delivery method
Choose a delivery method to continue
ScopeThe error belongs to the group, not to one option. It sits below the last row and is announced once.
TimingOn submit only. A group nobody has touched is not yet wrong.
ConsentA required single checkbox gets its error directly beneath it, and the label must state what is being agreed to — never "You must accept".

Async & failure

A switch applies immediately, which means it can fail immediately. This is the state teams forget, and the one users notice.

Saving…
×
Couldn't turn on vacation mode
Check your connection and try again
OptimisticMove the switch immediately, then reconcile. Waiting for the server before the thumb moves makes every toggle feel broken.
On failureRevert the control and explain inline, next to the switch. A toast alone leaves the user unsure which of six settings failed.
Never disableDo not disable the switch while saving — disabling removes it from the tab order and moves focus unexpectedly. Dim it instead.

Best practices

Do

Positive phrasing: checked means yes, unchecked means no.

Don't

A double negative. Ticking the box means not-unsubscribing, and nobody parses that correctly the first time.

Click targetLabel and description are always part of the target. The control alone is 20px; the row is 44px.
No mixingNever place checkboxes and switches in the same list. One applies on save and one applies now — identical layout, opposite behaviour.
DestructiveA switch that deletes data or makes something public gets a confirmation, despite being instant.
SizeControls never scale with the text. A 20px box beside 12px help text is correct.

Accessibility

Native inputsReal <input type="checkbox"> and type="radio", visually hidden and styled around. A styled div announces nothing and cannot be toggled by voice control.
SwitchA checkbox with role="switch", so it is announced as "on/off" rather than "checked".
Groups<fieldset> and <legend>, or role="radiogroup" with aria-labelledby. Without them the group label is never announced.
KeyboardCheckboxes and switches: Tab to reach, Space to toggle. Radios: Tab reaches the group, then arrow keys move and select within it.
IndeterminateSet the DOM indeterminate property, not just a visual dash — otherwise it is announced as unchecked.
Errorsaria-describedby from the group to its message, with aria-invalid on the inputs.
ContrastUnchecked border --border-strong at 3.1:1; checked fill 6.9:1. The check mark is white on green, never green on white.
