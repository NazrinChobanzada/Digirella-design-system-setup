Columns & alignment

Alignment is not taste. Left for text, right for numbers, and the reason is scanning: right-aligned figures line up their digits, so 1 284 and 642 can be compared without reading them.

ContentAlignDetail
TextLeftNames, titles, descriptions. The first column is always the row's identity.
NumbersRightPrices, counts, percentages. align: 'right' also switches the column to tabular figures.
DatesLeftRead as text, not compared digit by digit. One format across the whole table.
StatusLeftA Badge, never bare coloured text.
ActionsRightLast column, fixed width, icon-only or a Menu.
NeverCentreCentring destroys both the left edge of text and the digit alignment of numbers.

Sorting

Only sortable headers get a hover. A header that cannot be sorted must not change on hover — the user will click it, nothing will happen, and they will not trust the next header either.

Row interaction

Decide one thing per table: the row is a link, or the row holds controls. A row that is both produces clicks the user did not intend.

PatternRule
Row as linkThe whole row navigates. Cursor pointer, hover fill, and the identity cell is a real <a> so it can be middle-clicked.
Row with actionsThe row does not navigate. Actions live in the last column; the identity cell carries the link.
Inline editOnly for a single field, committed on blur, with an undo toast. Anything larger is a Drawer.
Nested controlsAny checkbox, menu or button inside a clickable row must stop propagation. Otherwise ticking a checkbox navigates away.

Always paginateTables get pages, not infinite scroll. A total count tells the user the size of the job; a footer needs to be reachable.
Sticky headerThe header row sticks while the body scrolls. Beyond about fifteen rows, column meaning is otherwise lost.
HorizontalIf columns must scroll sideways, pin the identity column. A scrolled row with no visible name is unreadable.
Page size24 by default. Offer 50 and 100 only where users genuinely export or audit.

Accessibility

SemanticsThe component renders CSS grid for layout control, so it must carry role="table", role="row", role="columnheader" and role="cell". Without them a grid table is a pile of divs to a screen reader.
Sortaria-sort="ascending|descending|none" on the active columnheader, and the header itself is a real <button>.
Selectionaria-selected on the row plus a labelled checkbox — "Select Wireless headphones", never "Select row 2".
AnnounceRow count changes go to a polite live region: "24 of 486 listings". Sorting and filtering are otherwise silent.
KeyboardTab reaches every interactive cell in reading order. Row actions are never hover-only — an action that appears on hover is invisible to keyboards and absent on touch.
ColourStatus never relies on colour alone. Selected rows carry a checked checkbox as well as the tint.
Targets46px comfortable rows and 38px compact rows both clear WCAG 2.5.8. Checkboxes get the full row height as their label target.
