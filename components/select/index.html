Components

Select · Combobox · TreeSelect

New

Three variants on one base: Select for short, fixed lists; Combobox when typing helps filter a long list; TreeSelect when options are nested. Multiple, clearable, creatable and remote are properties that switch on across variants. This page is the complete specification for the selection family.

Principles

A select holds a valueChoosing a row sets state — it does not navigate, submit, or rebuild the form. If picking a row runs a command, use an action menu: different keyboard model, no value, no validation.
Visible options beat hidden onesUp to about six options, a radio or checkbox group is better: all choices are readable at a glance and changing the answer takes one click instead of three.
Typing is an accelerator, not a gateIn a Combobox the full list still opens on click. Search makes a long list fast for people who know what they want — it must never be the only way to see what is available.
Every selection is reversibleA value can always be removed without reloading the page or inventing a "None" row in the data. Clearing is part of the control and is on by default.

When not to use

SituationUse insteadWhy
2–6 options, one choiceRadio groupAll options visible and comparable without opening anything

Search & autocomplete

List autocomplete filters the menu as you type and is the default for every Combobox. A Select does not filter — typing jumps to the first row starting with that character, cycling on repeats.

Match anywhereSubstring, not prefix: "man" finds "Azerbaijani manat". Case- and diacritic-insensitive — "turkiye" finds "Türkiye", "resad" finds "Rəşad".
Match the whole rowDescriptions, codes and — in a tree — the parent path all count, not just the visible label.
HighlightMark matched characters with --color-primary-subtle-hover so the reason a row appears in the list is visible.
Stable orderFilter, do not re-sort. An exact match may be pinned first; everything else keeps its original position.
No results"No matches for X" plus a way out — clear the query, or create the value when creatable.
Empty queryThe full list (static) or recent and suggested rows (remote). Focus never produces an empty menu.
Inline completionOnly for a single-select Combobox over a fixed list where one prefix has exactly one answer. Never with creatable, never with multiple, never on a remote list.

A property on every variant. Past about five rows, a multi-select should be a Combobox: as soon as several values are chosen, finding the ones not yet chosen is a search problem.

Creatable

A Combobox property only. It needs a query to create from — a Select has no typing, and in a tree there is no answer to "which parent does the new node belong to".

ExplicitA "Create X" row at the end of the filtered list, or Enter on an unmatched query. Never create silently on blur.
NormaliseTrim, collapse double spaces, apply the casing rule once, and match case-insensitively so the same value cannot be created twice.
DuplicatesIf the query already matches a row exactly, show that row instead of offering to create it.
No inline completionInline completion would overwrite the value the user is in the middle of inventing.

Static vs remote

Static: the whole list is in the browser; filtering is instant. Remote: every query asks the server — which introduces waiting, failure, and race conditions that all need designing.

DecisionStaticRemote
Use it whenThe list fits in memory and changes rarely — a few hundred rows of JSON is nothingThousands of rows, permissions decide what is visible, or data changes while the page is open
FilteringLocal, instant, no states to designServer-side; debounce 300 ms, minimum 2 characters
Before typingThe full listRecent or suggested rows — never an empty menu
While waitingn/aA loading row with the previous results kept underneath
Out-of-order repliesn/aIgnore any response older than the current query or the list flickers to stale rows
Failuren/a"Couldn't load options" with Retry inside the menu — an empty menu reads as "no results"
The selected valueAlways in the listStore id and label so the field can render a value whose row is not in the current results

Accessibility

These criteria apply to all three variants at every size in both themes.

1.3.1 — LabelA real <label for> tied to the field. The placeholder is not a label — it disappears as soon as there is a value.
2.1.1 — KeyboardEverything works from the keyboard: open, move, select, clear, close. No mouse-only expand controls in tree rows.
2.1.2 — No trapFocus is never trapped in the menu — Escape and Tab always get out.
2.4.3 — Focus orderClosing the menu returns focus to the field, so the tab order continues where the user left it.
2.4.7 — Focus visible2 px ring at 2 px offset on the field, the clear control, and tree expand controls.
2.5.3 — Label in nameThe accessible name contains the visible label word for word.
2.5.8 — Target sizeEvery target is at least 24×24 px, including the clear control, the token ×, and the tree expand control.
3.2.2 — On inputChoosing a value changes no context: no navigation, no submit, no form rebuild.
3.3.1 — Error identificationAn error names the field and what is wrong, is tied with aria-describedby, and the field carries aria-invalid="true".
4.1.2 — Name, role, valuerole="combobox" on the field with aria-expanded, aria-controls, and aria-activedescendant. role="listbox" on a flat menu, role="tree" on a nested one. Focus never moves into the popup.
1.4.3 — ContrastValue and placeholder text ≥ 4.5:1. Placeholder colour is a common failure — muted does not mean exempt.
1.4.11 — Non-text contrastField border, chevron and clear icon ≥ 3:1 against the page background.
1.4.12 — Text spacingRows grow taller with increased line height — no fixed row heights in pixels that clip descenders.
1.4.13 — Hover contentThe menu is dismissible (Escape), hoverable (pointer can move onto it), and persistent until dismissed or a value is chosen.

API

// One base, three variants. The variant is what the data looks like;
// everything else is a property.

<Select              // fixed flat list, no typing filter
  label="Status"
  options={statuses}
  value={value} onChange={setValue}
  clearable multiple
/>

<Combobox            // flat list + typing: the default above ~10 options
  label="Country"
  options={countries}          // omit when remote
  value={value} onChange={setValue}
  multiple creatable clearable
  inlineComplete={false}       // single + fixed list only
  remote={{
    load: q => api.search(q),
    debounce: 300,
    minChars: 2,
    recent: recentItems,
  }}
/>

<TreeSelect          // nested data
  label="Team"
  nodes={org}                  // [{ id, label, children?, disabled? }]
  value={value} onChange={setValue}
  multiple                     // cascades to descendants
  leafOnly={false}             // can a parent be the answer?
  loadChildren={id => api.children(id)}
  defaultExpanded={[currentBranchId]}
/>
