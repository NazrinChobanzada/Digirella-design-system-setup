Components

Select · Combobox · TreeSelect

New

Three variants on one base: Select for short, fixed lists; Combobox when typing helps filter a long list; TreeSelect when options are nested. Multiple, clearable, creatable and remote are properties that switch on across variants. This page is the complete specification for the selection family.

Guidelines

Principles

Five ideas explain most of the decisions on this page.

A select holds a value

Choosing a row sets state — it does not navigate, submit, or rebuild the form. If picking a row runs a command, use an action menu — it has a different keyboard model and holds no state.

Visible options beat hidden ones

Up to about six options, a radio or checkbox group is better: all choices are readable at a glance and changing the answer takes one click instead of three.

Typing is an accelerator, not a gate

In a Combobox the full list still opens on click. Search makes a long list fast for people who know what they want — it must never be the only way to see what is available.

Every selection is reversible

A value can always be removed without reloading the page or inventing a "None" row in the data. Clearing is part of the control and is on by default.

Default values are a liability in required fields

Pre-selecting a value means a wrong answer produces no error — the user never sees the validation prompt and submits silently. Avoid pre-selection in required fields unless the default is almost always correct. This applies equally to radio groups. When a default is needed, make it the system-recommended value and say so in the helper text.

Search & autocomplete

List autocomplete filters the menu as you type and is the default for every Combobox. A Select does not filter — typing jumps to the first row starting with that character, cycling on repeats.

List autocomplete — try typing "man", "eur", "lira"
Currency
Highlight token
Sennheiser
Sentey

Background tint (--color-primary-subtle-hover) marks the match — never bold, which shifts layout.

Match anywhere
Substring, not prefix: "man" finds "Azerbaijani manat". Case- and diacritic-insensitive — "turkiye" finds "Türkiye".
Match the whole row
Descriptions, codes and — in a tree — the parent path all count, not just the visible label.
Stable order
Filter, do not re-sort. An exact match may be pinned first; everything else keeps its original position.
No results
"No matches for X" plus a way out — clear the query, or create the value when creatable.
Empty query
The full list (static) or recent and suggested rows (remote). Focus never produces an empty menu.
Inline completion
Only for a single-select Combobox over a fixed list where one prefix has exactly one answer. Never with creatable, multiple, or remote.

Multiple

A property on every variant. Past about five rows, a multi-select should be a Combobox: as soon as several values are chosen, finding the ones not yet chosen is a search problem.

Combobox + multiple — menu stays open

Field
Show as many tokens as fit. Overflow as "+N more" — never a bare count. Past eight total, collapse to "N items selected" with the entity name.

When all selected items belong to one group, summarise as "Group (N)" — "Designers (3)" instead of "Nazrin, Narmin, Nigar". For a single-select field with grouped or hierarchical options, show a breadcrumb: "Designers / Nazrin".

Creatable

A Combobox property only. It needs a query to create from — a Select has no typing, and in a tree there is no answer to "which parent does the new node belong to".

Combobox + creatable — "Design system" is a new value
Tag
No matches for "Design system"
Create "Design system"
Explicit
A "Create X" row at the end of the filtered list, or Enter on an unmatched query. Never create silently on blur.
Normalise
Trim, collapse double spaces, apply the casing rule once, and match case-insensitively so the same value cannot be created twice.
Duplicates
If the query already matches a row exactly, show that row instead of offering to create it.
No inline completion
Inline completion would overwrite the value the user is in the middle of inventing.

Tree behaviour

Same field, same menu, nested rows. A tree earns its place when the hierarchy is part of the answer — "Platform" means something different under Engineering than under Operations.

Tree select — click ▶ to expand
Team
Expand control
18 px chevron on every parent row, separate hit area from the label. Clicking the label selects, clicking the chevron expands.
Indent
16 px per level. Past four levels, switch to a path breadcrumb in the row label instead.
Cascade
Multiple: selecting a parent selects its descendants. A partially selected parent shows an indeterminate dash.
What is selectable
Decide once: leaves only, or any node. Document the rule — silent non-cascading behaviour confuses everyone.
Search
Matches flatten into a list with their path as the description; ancestors auto-expand; clearing the query restores the previous expansion.
Default expansion
Expand the branch that contains the current value; collapse everything else. Never open everything at once.

Static vs remote

Static: the whole list is in the browser; filtering is instant. Remote: every query asks the server — which introduces waiting, failure, and race conditions that all need designing.

DecisionStaticRemote
Use it whenThe list fits in memory and changes rarely — a few hundred rows of JSON is nothingThousands of rows, permissions decide what is visible, or data changes while the page is open
FilteringLocal, instant, no states to designServer-side; debounce 300 ms, minimum 2 characters
Before typingThe full listRecent or suggested rows — never an empty menu
While waitingn/aA loading row with the previous results kept underneath
Out-of-order repliesn/aIgnore any response older than the current query or the list flickers to stale rows
Failuren/a"Couldn't load options" with Retry inside the menu — an empty menu reads as "no results"
The selected valueAlways in the listStore id and label so the field can render a value whose row is not in the current results

Accessibility

These criteria apply to all three variants at every size in both themes. Items marked high risk come up most often in review.

Labels and identification

The field must be identifiable both visually and to assistive technology.

  • 1.3.1A real <label for> tied to the field. The placeholder is not a label — it disappears as soon as there is a value. high risk
  • 2.5.3The accessible name contains the visible label word for word.
  • 4.1.2role="combobox" on the field with aria-expanded, aria-controls, and aria-activedescendant. role="listbox" on a flat menu, role="tree" on a nested one. Focus never moves into the popup.
  • 3.3.1An error names the field and what is wrong, is tied with aria-describedby, and the field carries aria-invalid="true". high risk

Keyboard and focus

The full lifecycle — open, navigate, select, clear, close — must be keyboard-operable.

  • 2.1.1Everything works from the keyboard: open, move, select, clear, close. No mouse-only expand controls in tree rows.
  • 2.1.2Focus is never trapped in the menu — Escape and Tab always get out.
  • 2.4.3Closing the menu returns focus to the field, so the tab order continues where the user left it.
  • 2.4.72 px ring at 2 px offset on the field, the clear control, and tree expand controls.

Interaction behaviour

How the field responds to input and which actions may trigger context changes.

  • 2.5.8Every target is at least 24×24 px, including the clear control, the token ×, and the tree expand control.
  • 3.2.2Choosing a value changes no context: no navigation, no submit, no form rebuild.

Contrast and spacing

Colour is the most common failure vector on this component — placeholder in particular.

  • 1.4.3Value and placeholder text ≥ 4.5:1. Placeholder colour is a common failure — muted does not mean exempt. high risk
  • 1.4.11Field border, chevron and clear icon ≥ 3:1 against the page background.
  • 1.4.12Rows grow taller with increased line height — no fixed row heights in pixels that clip descenders.
  • 1.4.13The menu is dismissible (Escape), hoverable (pointer can move onto it), and persistent until dismissed or a value is chosen.
