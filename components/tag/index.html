<div class="page__eyebrow">Components</div><h1 class="page__title">Badge &amp; Tag <span class="flag flag--lg">New</span></h1><p class="page__lede">Small markers attached to something else. A badge reports a state the system decided; a tag is a choice the reader can make. The difference is whether it can be pressed — and getting that wrong is the most common mistake with either.</p>
<div class="doc">


<section id="badge-or-tag">
<h2>Badge or tag</h2>
<p>Four names circulate for these — badge, tag, chip, lozenge — and they are not four components. This system ships two, and the decision between them is one question.</p>
<table><thead><tr><th style="width:110px"></th><th style="width:210px">Badge</th><th>Tag</th></tr></thead><tbody>
<tr><td>Is it pressable</td><td class="use">No. Never.</td><td class="use">Yes — it toggles, or it can be removed.</td></tr>
<tr><td>Who decided it</td><td class="use">The system. A state it is reporting: Draft, Live, Low stock.</td><td class="use">The reader. A filter they applied, or a value they picked.</td></tr>
<tr><td>Shape</td><td class="use">Rectangular at <code>--radius-xs</code></td><td class="use">Fully pill-shaped at <code>--radius-pill</code></td></tr>
<tr><td>Element</td><td class="use"><code>&lt;span&gt;</code></td><td class="use"><code>&lt;button&gt;</code>, so it is focusable and announced as pressed</td></tr>
</tbody></table>
<p>The shape difference is doing work here, and it is the same rule the <a href="../../foundations/shape/">shape</a> foundation applies to buttons: a rectangle reads as something the system stated, a pill reads as something you can toggle. If a marker is pressable it must be a pill, and if it is not pressable it must not be.</p>
<p><em>Chip</em> and <em>lozenge</em> are other systems' words. A chip is a tag; a lozenge is a badge. Neither is a third component.</p>
</section>

<section id="badge"><h2>Badge</h2>
<p>A status marker. Not interactive — it reports, it does not offer.</p>
<div class="demo">
<span class="badge-ix">Draft</span>
<span class="badge-ix" data-tone="success">Live</span>
<span class="badge-ix" data-tone="info">In review</span>
<span class="badge-ix" data-tone="warning">Low stock</span>
<span class="badge-ix" data-tone="danger">Rejected</span>
<span class="badge-ix" data-tone="brand">Featured</span>
</div>
</section>

<section id="tag"><h2>Tag</h2>
<p>A selectable filter chip. The ones on the left toggle; the ones on the right can be removed.</p>
<div class="demo">
<button aria-pressed="true" class="tag" type="button">Electronics</button>
<button aria-pressed="false" class="tag" type="button">Home &amp; living</button>
<button aria-pressed="false" class="tag" type="button">Fashion</button>
<span class="tag">Free shipping <button aria-label="Remove" class="tag__x" type="button">✕</button></span>
<span class="tag">Under ₼500 <button aria-label="Remove" class="tag__x" type="button">✕</button></span>
</div>
</section>

<div class="part" id="part-specification"><h2 class="part__title">Specification</h2></div><section id="spacing" data-part="Specification">
<h2>Spacing</h2>
<h3>Badge</h3>
<p>The tightest padding in the system, because a badge is a marker rather than an object.</p>
<table><thead><tr><th style="width:250px">Context</th><th style="width:150px">Value</th><th>Token</th></tr></thead><tbody><tr><td>Padding</td><td class="val">2 × 8</td><td class="tok">--badge-padding-y/x</td></tr><tr><td>Counter padding</td><td class="val">0 × 6</td><td class="tok">--badge-counter-padding-x</td></tr><tr><td>Dot or icon to text</td><td class="val">4</td><td class="tok">--badge-icon-gap</td></tr><tr><td>Badge to an adjacent title</td><td class="val">8</td><td class="tok">--badge-adjacent-gap</td></tr></tbody></table>
<p>In a table cell a badge inherits the cell padding — do not add margins around it.</p><p>A notification dot overlays its anchor at −4px from the corner, outside the box rather than inset.</p><p class="caption">Values are read from <code>tokens/spacing-components.css</code>. The rules behind them, and the two places this system diverges from the consensus, are on the <a href="../../foundations/spacing/">spacing</a> page.</p>
<h3>Tag</h3>
<p>Asymmetric on purpose: 12 on the label side, 8 on the icon side. An icon carries its own whitespace, so equal padding makes it look pushed away from the label.</p>
<table><thead><tr><th style="width:250px">Context</th><th style="width:150px">Value</th><th>Token</th></tr></thead><tbody><tr><td>Padding</td><td class="val">4 × 12</td><td class="tok">--tag-padding-y/x</td></tr><tr><td>Icon side</td><td class="val">8</td><td class="tok">--tag-padding-icon-side</td></tr><tr><td>Inner gap</td><td class="val">8</td><td class="tok">--tag-gap</td></tr><tr><td>Tag to tag</td><td class="val">8</td><td class="tok">--tag-gap</td></tr><tr><td>Row gap when wrapped</td><td class="val">8</td><td class="tok">--tag-row-gap</td></tr></tbody></table>
<p>A wrapped row of tags uses the same 8px vertically as horizontally, otherwise the second row reads as a separate group.</p><p>The dismiss icon stays 16px visually but needs a 24px hit area — 48 on touch.</p><p class="caption">Values are read from <code>tokens/spacing-components.css</code>. The rules behind them, and the two places this system diverges from the consensus, are on the <a href="../../foundations/spacing/">spacing</a> page.</p>
</section>

<section id="elevation" data-part="Specification">
<h2>Elevation</h2>
<p>None. A tag establishes itself with a border and a fill; a shadow would claim it floats.</p>
<table><thead><tr><th style="width:230px">Surface</th><th style="width:160px">Level</th><th>Token</th></tr></thead><tbody><tr><td>Rest, hover, selected</td><td class="val">none</td><td class="tok">—</td></tr></tbody></table>
<p>Selected tags fill with the brand colour rather than lifting.</p><p class="caption">The four levels and the rules behind them are on the <a href="../../foundations/elevation/">elevation</a> page.</p>
</section>
