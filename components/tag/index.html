Tags · Badge · Chip · Lozenge New

Four related but distinct markers — Badge, Chip, Tag, Lozenge — each with a different job, shape, and interaction model. Mixing them up is the most common mistake in display-layer design.

Overview

All four look like small labelled pills or rectangles. The shape, size, and interaction model are what separate them — not just the name.

Badge

What it is

A Badge attaches to a carrier element — an icon button, a navigation item, an avatar — to signal that something needs attention. The badge belongs to its carrier; it has no independent position. Two variants:

Dot8px circle. Signals presence only — "there is something here". No count.
CounterPill with a number. Shows exactly how many items need attention. Caps at 99+ to prevent overflow.

Chip

What it is

A Chip represents a value that has been selected or applied — a filter parameter, a chosen option in a multi-select, a tag added to a combobox field. It always lives inside a container that created it (a combobox input, a filter bar). Three key properties separate it from Tag and Lozenge:

Pre-determined valuesThe user selects from an existing set. A chip cannot carry a free-typed value — that would be an input token.
Single appearanceOne colour, one size, no tone variants. The meaning is always "this value is selected"; there is nothing else to communicate.
ClearableAlways removable. A chip with no ✕ is either a Tag or a Lozenge. If the selection cannot be un-done, it should not be a Chip.

Tag

What it is

A Tag is an identifier — a label applied to a record to categorise it or link it to related information. Unlike a Chip, it cannot be cleared by the user. Unlike a Lozenge, it is interactive: clicking it opens a popover with details about that identifier, or triggers navigation to a filtered view.

Tags always come in groups. When more than a threshold number would show (typically 3–4), the rest collapse into a counter chip (+N). Clicking the counter opens a popover listing the hidden tags, which may themselves be interactive.

Lozenge

What it is

A Lozenge is an inline status label. It communicates a record's current state — it never triggers an action. Use it wherever a status word appears in the data layer: table cells, list items, detail pages. The tone maps to a semantic category, not an arbitrary colour.

BrandFeaturedPromoted, highlighted, or platform-curated states. Use sparingly — brand fill competes with primary buttons.
One per recordA record has one status, so it gets one Lozenge. Two Lozenges next to each other usually means one of them should be a Tag or a property label instead.
Label the state, not the action"Awaiting dispatch" not "Dispatch". A Lozenge reports a state; if the reader should do something, put a button beside it.

Accessibility

Badge

  • 1.3.1The badge is decorative — the carrier element's aria-label must include the count: aria-label="Notifications, 5 unread". The visible badge is aria-hidden="true". high risk
  • 1.4.1The notification tone (red) must not be the sole signal. The carrier's accessible name conveys the same information.
  • 1.4.11The badge's border against the page background must reach 3:1 when the badge has no border of its own (dot variant relies on the page-colour 2px border).

Chip

  • 4.1.2The clear button needs aria-label="Remove [value]", not just "✕" or "Remove". high risk
  • 2.1.1Delete or Backspace while the chip is focused should remove it. The chip must be focusable.
  • 1.4.3Selected state colour (--surface-brand-subtle / --text-brand) must reach 4.5:1.

Tag

  • 4.1.2Tag is a <button>. Its visible label is its accessible name. The popover it opens needs aria-haspopup="dialog" or aria-haspopup="true" on the trigger.
  • 2.5.3The "+N" counter must have an aria-label that names the hidden items: aria-label="4 more tags: vendor-3, SKU-4821, export-batch-2, 3PL". high risk
  • 2.1.1The popover opened by the tag must be dismissible with Escape and trap focus while open.

Lozenge

  • 1.4.1The tone colour alone must not carry the meaning. The label text is the primary signal; tone reinforces it. "Rejected" in a neutral tone is still "Rejected". high risk
  • 1.4.3Text on coloured background must reach 4.5:1. Token pairs are validated: --text-success on --surface-brand-subtle, --text-warning on --surface-warning-subtle, etc.
  • 4.1.2Non-interactive — it is a <span>, not a <button>. Never add a click handler to a Lozenge; if the status is actionable, put a button beside it.
