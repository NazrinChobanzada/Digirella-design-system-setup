Alert

A page-level condition that persists until it changes. Unlike a toast it is part of the layout, so it can be re-read, and it can carry an action the user comes back to.

!
Verify your payout account
Payouts are held until the account is confirmed.
i
Dispatch is slower this week
Orders placed today ship within three business days.
✓
Buyer protection
Get your money back if the item doesn't match the description.
PlacementDirectly above the content it concerns. A page-wide alert sits under the header; a section alert sits inside that section.
DismissibleOnly if the condition is informational. An alert about a blocked payout must not be dismissible — the problem does not go away.
CountOne per view. Three stacked alerts train users to skip the region entirely.
Not forField-level validation, which belongs under the field. An alert is for conditions, not for form errors — except as a submit-time summary.
Alert · tone: success | info | warning | danger, title, action, onDismiss

Tooltip

One line, on hover and focus, naming a control. Because it does not exist on touch and disappears on any movement, it can never hold anything the user needs.

Free returns within 14 days
TestIf an icon needs a tooltip to be understood, it needs a visible label instead.
Delay400ms in, instant out. No delay makes tooltips fire while the pointer crosses the screen.
NeverInteractive content, links, or more than one line. All three are a Popover.

Esc alwaysEvery dismissible overlay closes on Escape, and closes only the topmost one. This is the one keyboard behaviour that must never have an exception.
Pause on hoverA toast the user is reading does not disappear mid-sentence. The timer resumes when the pointer leaves.

Positioning

AnchoredPopover, Menu and Tooltip attach to their trigger and follow it on scroll. They never detach or reposition mid-scroll.
FlipPreferred side first; flip to the opposite side only when there is not enough room. Never cover the trigger — the user must see what they opened.
ShiftSlide along the cross axis to stay in the viewport, with 8px minimum clearance from the edge.
FixedDrawer pins to an edge, Dialog centres, Toast pins to a corner. None of them are anchored to a trigger.

Accessibility

Rolesrole="dialog" with aria-modal for Dialog and Drawer; role="menu" and role="menuitem" for Menu; role="status" for Toast; role="alert" for a danger Alert and role="status" for the rest.
Live regionsToasts are polite, so they never interrupt what a screen reader is already reading. A blocking error is assertive — but that is an Alert, not a toast.
Trigger statearia-expanded and aria-controls on any button that opens an anchored overlay, so the state is announced before the overlay is reached.
Return focusEvery overlay that moved focus returns it to the trigger. Losing focus to the top of the page is the most common overlay bug in any system.
Inert backgroundDialog and Drawer mark the page behind as inert, so assistive tech cannot wander into content the sighted user cannot reach.
Not colour aloneEvery tone carries a glyph and a word as well as a colour — ✓ success, i info, ! warning, × danger.
TimingAuto-dismissal pauses on hover and focus, satisfying WCAG 2.2.1. Anything the user must act on never auto-dismisses at all.
