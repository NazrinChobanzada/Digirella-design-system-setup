With counts

A count is a decision aid, not decoration. "Drafts 0" tells the user not to bother; "Orders 3" tells them where to go first.

Tabs vs SegmentedControl

Both switch something. The difference is whether the content changes or only its form.

Tabs — different content
Listings Orders Payouts

Each panel holds different records. Switching answers "show me something else".

Segmented — same content
Grid List

The same records, drawn differently. Switching answers "show me this another way".

Nested tabs

One level. A second row of tabs inside a panel produces two active states competing for the same visual language, and users lose track of which row they changed.

HoverA neutral underline, never green. Two greens would make the hovered tab compete with the real selection.
DisabledAlmost always wrong. A tab with no content should show an empty state, not refuse to open — refusing tells the user nothing about why.

Selection & URL

DefaultThe first tab, or the one holding work that needs attention. Never remember the last tab across sessions — a user returning to an unexpected view thinks the page is broken.
URLThe active tab lives in the URL. A shared link opens the same view, and browser back moves between tabs rather than leaving the page.
SwitchingInstant. If a panel needs data, show its skeleton immediately — never delay the tab change until the fetch resolves.
StatePanel state survives switching away and back within a session: scroll position, filters, partially typed input.

Overflow

Two to six tabs. If a seventh is needed, the information architecture is wrong — not the component.

DesktopTabs never wrap and never scroll. A wrapped second row destroys the relationship between the row and its rule.
MobileHorizontal scroll with the active tab scrolled into view, and a fade at the edge so the overflow is visible.
Too manyMove to side navigation, or merge views and add a filter inside the panel.

Best practices

Do
Listings Orders Payouts

One or two words. The row is scannable in a single fixation.

Don't
Your active marketplace listings Orders awaiting dispatch Payout history

Sentences as tabs. The row is wider than the content it controls and cannot survive translation.

Stable setThe same tabs appear regardless of state. Tabs that appear and disappear make the interface unlearnable.
No actionsA tab switches a view. Never put "Create listing" in the tab row — that is a button, and it belongs in the page header.
PositionDirectly above the panel, sharing its width. A tab row that does not visually own its panel is just decoration.
Equal weightTabs are peers. If one view is dramatically more important, it is the page and the rest are secondary navigation.

Accessibility

Rolesrole="tablist" on the row, role="tab" with aria-selected on each, role="tabpanel" with aria-labelledby on the panel.
KeyboardTab moves into the row, then ← → move between tabs, Home and End jump to the ends. Only the active tab is in the tab order — arrow keys, not Tab, move between them.
ActivationAutomatic: moving the arrow key changes the panel. Acceptable because panels are cheap here; if a panel were expensive, manual activation with Enter would be required instead.
FocusVisible ring on the tab, and the panel is reachable by Tab immediately after — never trapped behind the whole row.
Not colour aloneThe active tab carries both a 2px rule and a weight change, so the selection survives greyscale and low vision.
CountsIncluded in the accessible name: "Sold, 8 items" rather than "Sold 8".
