A popover is a small floating panel anchored to a trigger element that surfaces contextual content or lightweight actions on demand.

Overview

Popovers occupy a middle ground between tooltips and dialogs. A tooltip shows a brief label on hover and disappears when you move on. A dialog blocks the page and demands a decision. A popover opens on click, can hold interactive content — a form, a set of action buttons, a small summary card — and dismisses without requiring any explicit confirmation. Its anchor arrow keeps the spatial relationship between trigger and content clear even when content shifts position to stay on screen.

Guidelines

When to use

Use a popover when you need to show richer content than a tooltip can hold, but the context does not warrant interrupting the page with a dialog. The key distinction is interaction: if the content inside can be acted on — a button clicked, a field filled, a link followed — it needs a popover, not a tooltip.

Content guidelines

A popover is small and temporary. Its content should match that: one topic, no more than one or two actions, no scrolling.

Keep to one topic

A popover that tries to serve two purposes — explain something and let the user edit it — becomes a dialog in disguise. If the content needs more than about four lines of text or two actions, it belongs in a drawer or dialog where it has room to breathe and the user's full attention.

Allow interaction, not flow

A popover can hold a button, a toggle, a short text field, or a few radio buttons. It cannot hold a multi-step flow. If pressing an action inside the popover opens something else, open that thing and close the popover first — do not overlay layers.

When to include a close button

Include an explicit ✕ close button when:

  • The popover contains a form with input fields — the user needs to be able to leave without submitting.
  • The popover is likely to stay open for more than a few seconds.
  • The trigger is far from the edge of the screen and the user might lose track of how to dismiss it.

Omit the close button for simple informational popovers that close on any outside click — adding a button adds visual weight without any real benefit when click-outside already handles dismissal.

Anatomy

Anatomy

Status filter
  • ① Trigger element — the control that opens the popover on click. Any interactive element can serve as a trigger: a button, an icon button, a text link. It receives aria-expanded and aria-controls attributes.
  • ② Popover container — the floating panel. It sits in the DOM near the trigger and is positioned via a positioning library (Floating UI, Popper). It carries role="dialog" when interactive, or is left implicit when purely informational.
  • ③ Arrow / caret — an optional decorative pointer that visually connects the panel to the trigger. Omit it when the trigger and panel are close and the spatial relationship is obvious without help.
  • ④ Body content — the panel's contents: text, form fields, action buttons, or any combination. There is no scroll; content that overflows belongs in a drawer.
  • ⑤ Close button — an optional ✕ in the top corner. Include it when the popover holds a form or is likely to remain open for an extended interaction. Omit it for simple read-only content.

Placement

Popovers are positioned relative to their trigger. The preferred position is below the trigger (bottom-start), which follows reading order and feels natural. The positioning engine auto-flips to the opposite side when the preferred side would overflow the viewport.

Offset

The panel sits 8px from the trigger edge — enough to clear the trigger's focus ring without visually disconnecting the two. The caret, when present, bridges the gap. Do not reduce the offset below 4px — a panel flush against its trigger feels like a visual collision.

Behaviour

Triggers

Popovers in Digirella are click-triggered by default. Hover-triggered popovers are an option but come with significant accessibility costs and should be treated as an edge case.

Click-triggered (preferred)

Click is safer for interactive content. The user opens the popover intentionally, can interact with its contents at their own pace, and dismisses it deliberately. It works with keyboard and touch without any special handling. The trigger button gets aria-expanded="true" when the popover is open and aria-expanded="false" when closed.

Hover-triggered (use with care)

Hover-triggered popovers are appropriate only for purely informational content with no interactive elements inside. If you use hover, follow these constraints:

  • Add a 300ms open delay to prevent accidental triggers as the cursor moves across the page.
  • Keep the popover open when the cursor moves from the trigger into the panel — the panel is a valid hover target.
  • Add a 100ms close delay so the popover does not vanish as the cursor moves between trigger and panel.
  • Make the same popover openable by keyboard (focus + Enter or Space on the trigger), since hover alone excludes keyboard users.
  • Never put interactive elements inside a hover-triggered popover. Popovers that can be hovered over to reach a button inside create an unreliable acquisition path for motor-impaired users.
Touch devices have no hover. A hover-triggered popover that cannot also be opened by tap effectively hides its content from touch users. Test on mobile before committing to hover.

Dismissal

A popover should be easy to dismiss without completing its task. Three mechanisms cover all input types.

Click outsideClicking or tapping anywhere outside the popover panel — including the trigger itself if it is already open — closes the popover. This is the primary gesture for pointer and touch users.
Escape keyPressing Escape closes the popover from any focused element inside it and returns focus to the trigger. This is the primary gesture for keyboard users and must always be implemented.
Close buttonWhen a ✕ close button is present, activating it closes the popover. Focus returns to the trigger.
Completing the actionWhen the popover contains a form, submitting it (primary button) closes the popover. Cancelling it also closes the popover and discards any changes without confirmation — the task is lightweight enough that no confirmation is warranted.

What does not close the popover

Scrolling the page does not close the popover — the anchor positioning keeps the panel visible and connected to the trigger. Opening a different popover closes the current one. Only one popover should be open at a time.

Accessibility

The correct ARIA role for a popover depends on whether it holds interactive content. Get this wrong and screen reader users either cannot reach the content or cannot navigate away from it.

Role selection

  • 4.1.2Use role="dialog" when the popover contains interactive content (buttons, form fields, links). This signals to the screen reader that focus will enter a contained region. Without it, interactive elements inside the popover may be unreachable or confusing. high risk
  • 4.1.2Use no explicit role (or role="tooltip") only for purely informational popovers with no interactive content. A tooltip role is announced differently — it is not a region the user can navigate into.
  • 4.1.2When using role="dialog", include aria-label or aria-labelledby to give the popover an accessible name.

Trigger attributes

  • 4.1.2The trigger element carries aria-expanded="false" at rest and aria-expanded="true" when the popover is open. This tells screen reader users that the button controls something. high risk
  • 4.1.2Link the trigger to the popover panel with aria-controls="[panel-id]".
  • 4.1.2When the popover is a tooltip-role panel, use aria-describedby="[panel-id]" on the trigger instead of aria-controls.

Focus management

  • 2.4.3When a role="dialog" popover opens, move focus to the first focusable element inside it — usually the close button or the first field.
  • 2.1.2For interactive popovers, trap focus inside the panel — Tab and Shift+Tab cycle through the panel's focusable elements without reaching the page behind.
  • 2.4.3On close, return focus to the trigger element that opened the popover.

Keyboard

  • 2.1.1Escape closes the popover from any focused element inside it.
  • 2.1.1Enter or Space on the trigger opens the popover. Closing does not require Enter — click-outside and Escape cover both pointer and keyboard users.
