Choosing a control

Answer three questions in order: how many can be chosen, how many options exist, and whether the options have structure. The answer is always one control — if two seem to fit, the set is too large for the simpler one.

ControlChoicesOptionsUse when
RadioOne2–5Every option should be visible without a click. Shipping speed, condition.
SelectOne3–10The list is short enough to scan but long enough to fold away. Sort order, currency.
ComboboxOne10+Scanning is slower than typing. City, brand, seller.
MultiSelectMany5+Several answers are normal and must stay visible. Categories, regions.
Checkbox groupMany2–5Short list, no search needed. Notification types.
TreeSelectOneAnyOptions are a hierarchy the user must see to understand. Category tree.
Do

Two options, both visible. The user compares them without a click.

Don't
Standard

A Select hides half the decision behind an interaction, for no gain in space.

Single select

The default. A native <select> under design-system chrome, so it inherits mobile pickers and platform keyboard behaviour for free.

Multi-select · tags

Same control, selections shown as removable tags. Use when each choice must stay visible and individually removable — the field is a summary of the answer, not a count of it.

Tree select

A hierarchy the user must see to navigate. Only leaves are selectable; parents expand. The field shows the full path, because a leaf label alone is often ambiguous — "Cases" means nothing without its parent.

Opening & closing

TriggerResult
Click fieldOpens. Clicking again closes — the field is a toggle, not a one-way door.
Focus via TabDoes not open. Keyboard users open with ↓, Enter or Space, so tabbing through a form never floods the screen with menus.
Select an optionSingle: closes and returns focus to the field. Multi: stays open.
Click outside · EscCloses, discarding nothing — selections apply immediately, so there is no cancel.
Scroll the pageThe list follows its field. It never detaches or repositions mid-scroll.

The list opens downward, flipping above the field only when there is not enough room below. It never covers its own field — the user must be able to see what they are changing.

Filtering

DebounceLocal lists filter on every keystroke. Remote lists wait 250ms and show a loading row rather than an empty one.
ResetThe query clears when the list closes. Re-opening always shows the full set — a stale filter that hides options looks like data loss.
No matchThe empty message names what was searched and offers the way out: "No brands match 'xyz'."
SelectedThe current value stays visible even when it does not match the query, marked with a check.

Loading, empty, error

Three states that get skipped in design and then improvised in code. Specify them.

Loading

Three skeleton rows, never a spinner. The list keeps its height so nothing below it jumps.

Empty
No brands match “xyz”
Check the spelling or clear the filter

Names the query and offers a route out. Never a bare “No results”.

Overflow & truncation

Long labelsTruncate with an ellipsis at the field, never in the list. The list is where the full text has to be readable.
Long listsScroll at 260px, roughly six rows. Virtualise past 200 options; below that the DOM cost is irrelevant.
Field widthThe list matches the field width and never exceeds it. A menu wider than its trigger reads as a different element.

OrderFrequency first, then alphabetical. Never database order — that is an implementation detail leaking into the UI.
DependentA field that depends on another (city after country) stays disabled with a hint, rather than showing an empty list.
WidthSize to the longest expected value, not to the container. Six fields of six different widths look broken.
CountShow result counts when they change the choice ("Headphones 1 284"). Omit them when they are noise.
DisabledDisable an option only with a visible reason nearby. Otherwise omit it — an unexplained dead row is worse than absence.

Accessibility

Rolesrole="combobox" on the field with aria-expanded, aria-controls and aria-activedescendant; role="listbox" on the list; role="option" with aria-selected on rows.
LabelA real <label for>. aria-label only where no visible label can exist, and then it must match the visible context.
AnnounceResult counts go to a polite live region: "12 categories available". Silent filtering leaves screen-reader users with no feedback.
FocusNever leaves the field while the list is open — the highlight moves via aria-activedescendant, so Esc always returns somewhere predictable.
ContrastField boundary --border-control at 3.1:1, option text 4.9:1 or better, selection marked by a check as well as colour.
TargetsOption rows 44px tall including padding, clearing WCAG 2.5.8 with room to spare.
