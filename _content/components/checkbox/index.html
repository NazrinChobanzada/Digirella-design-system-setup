Checkboxes let people select one or more options from a set, or toggle a single setting on or off.

Overview

A checkbox is a binary control: checked or unchecked. Group several together and people can pick any combination. Use a single one to confirm agreement or toggle a setting that takes effect after a Save. Because each option is independent, checking one never affects the others — that is what separates a checkbox from a radio button.

Every example on this page is the real component. Press it, tab to it, try keyboard navigation.

Guidelines

When to use

Checkboxes are the right control when any combination of options is valid, when a single setting can be toggled, or when an action requires explicit consent. They are the wrong choice when exactly one option must be selected — that is a radio button — and when there are so many options that scanning a list is impractical — that is a Select or Combobox.

Groups

Individual checkboxes rarely appear alone outside of consent or agree-to-terms patterns. When you present several together, group them with a <fieldset> and a <legend>. The legend is the group label — it names what the set of checkboxes is about, not just "Options".

Spacing

Stack checkboxes vertically with --space-3 between them. That gives the touch target a comfortable gap without making the list feel airy. Horizontal groups are only appropriate when you have two options and the labels are very short — three across is already a risk at small viewports.

Field-level errors

When a group has a validation rule — for example "select at least one" — place the error message below the group's last item, not next to individual checkboxes. Use aria-describedby on the <fieldset> to associate the error with the group.

Content guidelines

Label wording

Write checkbox labels as short noun phrases or verb phrases that describe the option itself — not the action of selecting it. "Receive order confirmations" is clear. "Check to receive order confirmations" repeats what the widget already communicates and adds noise. Keep labels to one line where possible; if a label wraps it is likely too long.

Do name the option directly. The interaction is implied by the control.
Don't explain the interaction in the label — it turns a two-word option into a sentence.

Description text

Use a description (the .choice__desc element) only when the label alone would be ambiguous. A description that restates the label in different words adds length without helping. Keep descriptions to one sentence and write them in sentence case.

Never invert meaning

A checked state should always mean the positive or active condition. A checkbox labelled "Disable notifications" that becomes active when checked inverts the semantic meaning of the control — what looks like agreement is actually a negation. Rename it "Notifications" and trust the checked/unchecked states to carry the meaning.

Do write in the affirmative — checked means on.
Don't use a negative label — checked meaning "don't" is confusing.

Behaviour

Indeterminate

The indeterminate state represents a parent checkbox whose children are partially selected — some on, some off. It is a display state only: it cannot be reached by a user click and must be set in JavaScript with element.indeterminate = true. The browser renders a dash in place of the checkmark to signal that the selection is mixed.

Indeterminate is a display state, not a value. input.indeterminate does not affect the underlying checked boolean. The form submission still sends the last checked/unchecked value. Reset it explicitly when the user changes the parent.

The transition rule when a user clicks an indeterminate parent is a product decision, but the most common pattern is: indeterminate → checked (selects all children) → unchecked (deselects all children). This makes the parent a "select all" toggle once it enters the cycle.

Select all

A "Select all" checkbox in the header row of a list or table is a specific application of the parent/children pattern. It appears above or to the left of the item list, checks all items when activated, and moves to indeterminate when some but not all items are manually selected.

The header checkbox reflects the state of all rows. Click it to toggle all, or change individual rows to see the header respond.

When building a select-all in a table, use a <th scope="col"> for the header cell. Individual row checkboxes should have aria-label values that describe the row — "Select order #4821" — so each one is announced correctly to a screen reader scanning the table.

Accessibility

Checkboxes are native form controls, so most of the semantics come for free. The common failures are naming gaps and grouping errors.

Individual checkbox

  • 1.3.1Use a native <input type="checkbox"> inside a <label>. Clicking the label text activates the input and the association is announced automatically. high risk
  • 2.1.1Space toggles a focused checkbox. Enter does not — only Space. Both Tab and Shift+Tab move between checkboxes.
  • 2.4.7A visible focus ring, using --focus-ring, on every focusable checkbox.
  • 1.4.11The unchecked box border reaches 3:1 against its background. The checked fill at --color-primary passes with room. high risk
  • 1.4.3Label text reaches 4.5:1 in all states, including disabled.
  • 2.5.8The touch target meets the 24×24px minimum. Our controls are 16px but the label extends the hit area.

Groups

  • 1.3.1Wrap related checkboxes in a <fieldset> with a <legend>. The legend becomes the group's accessible name, announced before each option. high risk
  • 3.3.2When at least one selection is required, include a visible indicator (asterisk or "(required)") and associate a validation error via aria-describedby.
  • 3.3.1Surface the error in text, not colour alone. "Select at least one option" beats a red border with no message.

Indeterminate state

  • 4.1.2An indeterminate checkbox is announced as "mixed" by ARIA-aware screen readers. No extra ARIA is needed when using a native input with .indeterminate = true.
  • 4.1.3When the state changes programmatically (e.g. all children deselected), the parent's indeterminate state must update to match. A stale "mixed" announcement is a live-region failure. high risk
