The size, weight and line-height for every piece of text in the product — from a button label to a dialog title. Product text sits at 14/20, long reading at 16/24, and nothing a person must read to act goes below 12.

Principles

Nine ideas sit behind every number on this page.

One base size, and it is 14

Product body text sits at 14px. 16px is for long reading and marketing pages. Everything else is derived from those two.

Three to five sizes is enough

In most product screens 12, 14, 16 and 20 carry everything. The rest of the scale exists for page titles, metrics and marketing — not for adding another level of hierarchy inside a form.

Line-height lands on 4px

Each size is paired with a line-height that is a multiple of 4, so text aligns to the same grid as spacing. A 14px label with a 20px line sits exactly five spacing units tall.

Weight before size

Inside a component, change the weight or the colour before you change the size. A section heading inside a card is 14px at 600, not 16px at 400 — the card stays compact and the hierarchy still reads.

Tracking follows size

Large text tightens slightly, body text is left alone, and small text opens up. Uppercase opens up further, because capitals set without extra space collide.

12px is the floor

Below 12px nothing is comfortably readable on a screen. The 11px step exists for dense metadata only — a timestamp in a crowded table row — and never for anything a person has to read in order to act.

Inputs go up on mobile

iOS Safari zooms the whole page when a focused field holds text under 16px. So field values rise to 16px on small screens — the only place type gets larger as the screen gets smaller.

Size in rem, not px

Someone who sets a larger default font size in their browser should get larger text. That works when sizes are in rem and silently fails when they are in px.

Type is not layout

Never set a fixed height to control text. Let the line-height set the height, keep single-line labels to one line with an ellipsis, and let translated strings wrap. A control that is exactly tall enough for English is too short for everything else.

Typeface

Public Sans for everything, and IBM Plex Mono for technical data — codes, SKUs, order numbers.

Public Sans has a generous x-height and clear numerals, which is what lets the product base sit at 14px without straining. A face with a smaller x-height would need to run a step larger for the same legibility, so check any replacement at 12 and 14px before adopting it.

Four levels of emphasis at a single size. This is how a dense screen keeps a hierarchy without growing the scale.

Medium 500 — button labels, active navigation, selected rows

Regular 400 — body and input values

Regular, muted — secondary information

Three weights carry the product. Adding a fourth for ordinary text does not create a new level of hierarchy — it creates two levels that are hard to tell apart.

Measure

Set a maximum width on any block of running text. At 14px that is roughly 520–560px. Past it, the eye loses the start of the next line on the return sweep, and reading slows down even though nothing on the page has changed.

A column held to a comfortable measure lets the eye find the start of each new line without searching for it.

Around 65 characters per line.

A line that runs the full width of a wide container makes every return sweep longer, so the eye loses its place between lines and reading slows.

Unbounded, it stretches with the screen.

Inside a fixed-height control, use the tight pairing so the text centres cleanly; for paragraphs, use the pairings above.

Truncation

ContentRule
Names, labels, table cellsOne line with an ellipsis.
Descriptions, previewsClamp to two or three lines, so cards in a row stay the same height.
Numbers, IDs, amountsNever truncate. Wrap the container or drop a column instead — a clipped price is a wrong price.

Whatever is truncated keeps its full text in a title or a tooltip, so the ellipsis hides length rather than information.

Short English labels grow the most when translated, and the product's own languages are among the longer ones.

Give buttons and tabs room to grow, and never set a width from the English string. A button sized to "Save changes" is a button that clips or wraps in the languages the product actually ships in.

Components with fixed heights break first. Use a minimum height plus padding, so a longer label or a taller script can push the control rather than overflow it.
