Principles

PrincipleWhy
Ask lessEvery field is a reason to abandon. Delete anything you will not act on, and derive what you can — city from postcode, currency from country.
One columnA single vertical path is completed faster and with fewer errors than any multi-column arrangement.
Group by meaningRelated fields under one heading turn twelve questions into three tasks.
Validate lateTell people they are wrong after they have finished being right, not while they type.
Never lose inputNo error, dismissal or navigation clears what the user typed. Retyping an address is where forms die.

One column

A single column gives one unambiguous path down the form. Two columns force the user to decide where to look next at every row, and Z-shaped scanning causes skipped fields.

SizeTwo to six fields per group. A single-field group is a heading doing no work; ten fields is not a group.
Spacing12px between fields, 32px between groups. That ratio alone communicates the structure without any dividers.
DividersOnly where headings are not enough — long forms, or groups that look alike. Space is the primary separator.
OrderEasy and familiar first. Asking for a tax number before a name makes the whole form feel bureaucratic.

Action row

Do

Left-aligned with the fields, primary first. The eye reaches it by continuing straight down.

Don't

Centred, with cancel first: no anchor to the form, and the destructive-adjacent option leads.

AlignmentLeft in forms, matching the field edge. Right-aligned only inside dialog footers, where the container is the anchor.
OrderPrimary, then Cancel as ghost. One primary per form.
StickyFor forms longer than a viewport, pin the action row to the bottom with a border and card background — never make the user scroll back to submit.
Never disableDo not disable submit until the form is valid. The user cannot then discover what is missing; submit and show the errors instead.

Validation timing

MomentRule
While typingNever an error. Only live constraints the user is working against — a character counter, a password meter.
On blurValidate a field the user filled and left. Never one they tabbed through untouched.
On submitValidate everything, focus the first error, summarise above the form when more than two failed.
After fixingClear the error the moment the value becomes valid — do not wait for another blur.
Server errorsMap back to the specific field wherever possible. "Something went wrong" at the top of a form is a dead end.

Required & optional

Mark the minority. If most fields are required, mark the optional ones; if most are optional, mark the required ones. Marking both is noise; marking neither is a guess.

The word"(optional)" in regular weight beside the label. Unambiguous in every language and read aloud correctly.
Never an asteriskAn asterisk needs a legend, legends get skipped, and screen readers announce it as "star".
Better stillDelete optional fields. A field nobody has to fill is a field nobody needed to see.

Submitting

Cancel
Lock the buttonDisable submit for the duration so it cannot be double-fired, but never disable the fields — the user should still be able to read what they sent.
Keep widthThe button keeps its size while loading. A shrinking button moves the target under the pointer.
SuccessNavigate, or confirm with a toast. Never leave the user on an unchanged form wondering whether it worked.
FailureKeep every value, show the error where it belongs, and leave the form ready to resubmit.
AutosaveFor long forms, save drafts silently and show a quiet "Saved" timestamp. Never a toast per field.

Long forms & steps

Past about twelve fields, one page becomes a wall. Split by task, not by arbitrary count, and only when each step is independently meaningful.

  1. ✓Cart
  2. 2Delivery
  3. 3Payment
Three to five stepsEach a coherent task with its own name. "Part 2 of 6" names nothing and reads as a chore.
Validate per stepErrors are caught before moving on, so nobody reaches step four to learn step one was wrong.
Back is freeReturning to a previous step preserves everything and never re-validates unrelated fields.
AlternativeSections with a sticky in-page nav often beat steps: the user sees the whole scope and can jump around.
URLEach step gets one, so browser back moves between steps rather than leaving the flow.

AutofillCorrect autocomplete and name attributes throughout. A checkout that cannot autofill costs the user thirty seconds and you a percentage of orders.
Accept messy inputNormalise phone numbers, card numbers and postcodes yourself. Rejecting spaces is the system refusing trivial work.
KeyboardEnter submits a single-purpose form. Tab order follows visual order with no exceptions.
Exit safelyNavigating away from a dirty form asks first. Leaving it silently loses everything.
No reset buttonNobody wants to clear a form they just filled, and everybody occasionally clicks it by mistake.

Accessibility

Real formA <form> element with a submit button, so Enter works and browsers can autofill. A div with a click handler breaks both.
Groups<fieldset> and <legend> for every group, so the heading is announced with each field inside it.
LabelsEvery field has a real <label for>. Placeholder text is not a label and is not reliably announced.
Errorsaria-invalid plus aria-describedby to the message, and the summary in a live region focused on submit.
AutocompleteCorrect tokens satisfy WCAG 1.3.5 and help everyone, not only assistive-tech users.
Focus orderDOM order matches visual order. Never reorder fields with CSS — the tab order silently diverges from what is on screen.
StatusSubmission progress and success are announced politely: "Saving", then "Address saved". A visual spinner alone announces nothing.
